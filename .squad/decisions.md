## Round 11 -- 2026-08-03T10:35:00-07:00 -- the merge=union condensation defect: found, measured, and fixed

### 2026-08-03T10:35:00-07:00: Scribe — `merge=union` cannot represent a deletion; every past Scribe condensation on an agent who subsequently merged was silently reverted, and the mechanism is now fixed and demonstrated

**By:** Scribe, defect surfaced by Switch. **What:** `.squad/agents/*/history.md` was declared `merge=union` in `.gitattributes`, chosen so concurrent agents appending to the same history never conflict. Union merge computes the set of unique lines present on *either* side of a merge and has no concept of a deletion. Scribe's condensation of `switch/history.md` (`a9d8693`, 92,884 → 13,914 bytes on main) deleted ~79 KB of superseded prose; `squad/switch` had forked *before* that condensation and, when merged (`9e20c25`), the union driver faithfully unioned the condensed file's lines with the stale branch's full pre-condensation copy — reinstating every deleted line. Result climbed to 106,797 bytes at the merge, then grew normally to 113,127 bytes by HEAD (`8ac1172`) as further sessions were appended on top of the reverted body. Confirmed by walking the file at each commit (`a9d8693`=13,778 committed bytes, `9e20c25^2`=93,058, `9e20c25`=106,797). **Damage audit across all agents with a summarisation commit in their history (`db07e0d`, `f6f98e2`, `1d52725`, `775a341`, `a9d8693`):** Mouse's condensation (`775a341`, 58,205 → 28,133 bytes) held — no branch merge of `.squad/agents/mouse/history.md` occurred after it; the commits following are a linear append chain, not a union-merge of a diverged copy, so nothing was reverted (current 47,132 bytes reflects normal growth, not resurrection). Switch's is the only condensation known to have been reverted. **Fix:** kept `merge=union`'s no-conflict guarantee for genuine concurrent appends but made deletions survive, via a new custom driver `merge.squad-history` (`.squad/tools/history_merge_driver.py`, registered per-clone by `.squad/tools/setup-merge-drivers.ps1` since driver commands live in `.git/config`, which git never versions — **every worktree, including scribe-1/scribe-2's shared one, must run the setup script once, or that worktree silently falls back to a different merge behaviour**). The driver treats whichever side of a merge is *shorter than the 3-way merge base* as an intentional condensation and keeps it as the skeleton, then appends only lines from the other side that are genuinely new relative to the base (real concurrent agent writes) — lines the condensation removed are, by construction, already in the base set and are excluded from the "new" set, so they cannot be resurrected. `.gitattributes` now routes `.squad/agents/*/history.md` and `.squad/decisions.md` (same deletion-vs-archival risk applies to Tier-1/Tier-2 archival) through `merge=squad-history` instead of `merge=union`. **Demonstrated, not just reasoned about:** built a throwaway sandbox repo, condensed a history.md on `master` after branching, appended a new session on the forked branch, and merged. Plain `merge=union` reproduced the exact defect (old condensed-away sessions came back verbatim). `merge=squad-history` on the identical inputs kept the condensation and correctly included the new branch's line, nothing else. **Then applied for real:** re-condensed `switch/history.md` (113,127 → 22,848 bytes) using the now-holding mechanism — richer than the reverted first attempt (22,848 vs 13,914 bytes) because it retains full detail for the KV-arena session and a fuller mid-history digest rather than a terser paragraph. **Why:** a fix reasoned about but not exercised against the concurrency case it must survive is exactly what produced this defect the first time.
