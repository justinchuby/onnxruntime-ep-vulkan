### 2026-08-02T02:03:46-07:00: The anchor exemption decides Phi-3.5's retention, not the economics arm — wrong by 16,268× and accepted anyway, as a signed bound (consolidated)

**By:** Mouse (`mouse-which-arm-claimed-phi35`, `mouse-ledger-provenance-and-the-bound` §5), Morpheus (`morpheus-anchor-exemption-decides`, `morpheus-prefer-the-bound-you-can-sign`)
**Why consolidated:** one question (which arm retained the island?), one counterfactual experiment (Mouse), and one ruling that both accepts the finding and narrows what may be concluded from it (Morpheus) — a single episode told from measurement through governance.

**The question and the counterfactual:** shipping reports `viable_islands_retained: 1`, `net_benefit_sole_island_overrides: 0` — the net-benefit predicate passed on its own, the sole-island override did not fire. Holding everything else fixed and toggling one input: exemption on → retained 1/overrides 0; exemption off → retained 0/overrides 1, reason `TRANSFER_DOMINATED`. **The economics arithmetic is reached, and when allowed to decide it declines the graph we ship**, at every swept `fixed_ns`, because the byte estimator's boundary was ~10⁵ too large (§7.12.1). Fixing the estimator's first defect (internal island edges charged to the boundary) closed 89.2 GB → 13.9 GB and flipped the override to 0 on its own economics — but `slot_bytes` still substitutes 128 for every unknown runtime-extent dimension, and every Phi-3.5 boundary tensor is runtime-extent: residual ratio **~16,268×**.

**Morpheus's ruling — the concurrence is declined, the bound is accepted:** "the economics arm now agrees with the exemption" is refused as corroboration — *agreement between two things fed the same fabricated input is not a second opinion; an identity whose two sides come from the same source is a falsifier that cannot fire.* What survives is an inequality, not an agreement: `transfer_ns` is monotone increasing in bytes, the gate claims at 13,936,509,056 B, the true instrumented boundary is 856,720 B (smaller) — so the claim survives a 16,268× adversarial inflation of the term opposing it. **§10.0.4 gains a third form: prefer the count, prefer the ratio, prefer the bound you can sign.** The licence is narrow and directional: a modelled quantity known wrong is quotable as a bound only when the model is monotone in the perturbed input, the perturbation's sign is independently established for that window, and it is used only in the direction the sign licenses — Phi-3.5's decode window (extent 1) over-counts, but a long-prefill window (extent >128) under-counts and **the bound evaporates rather than weakening**; named as a standing falsifier.

**What is withdrawn vs. what stands:** the claim that the partitioner's economics model justifies retaining this island is withdrawn — no such justification was ever earned, on this or any model, since every non-trivial transformer island contains an anchor op (MatMul/Gemm/Conv/Attention/…) and 3c never sees an anchor-bearing island. **What is not withdrawn: the result** — 355/363 nodes in one fused island, `MATCH` on both devices — a count and a verdict, both observed, invariant to why the island was retained (§10.0.4). Naming fixed to match: `Island::MEASURED_PHI35_DEV0` → `ESTIMATED_PHI35_DEV0_INTERNAL_EDGES_COUNTED` (a constant named MEASURED holding a 6.4×-wrong estimate, kept beside the true `_REAL_BYTES` constant rather than overwritten — only the name was wrong); the `TRANSFER_DOMINATED` test renamed to say which estimate it is about. **Cross-model risk flagged, not yet closed:** the exemption's warrant ("an anchor is by definition heavy enough to justify a boundary") is asserted, not measured, and is now the sole term deciding every production partition on both devices — falsifier: a future anchor-bearing island that genuinely should be declined (a small MatMul inside large boundary traffic, an edge-shape or small-model graph).

### 2026-08-02T02:03:46-07:00: The §8.9 proof ledger lands; criterion 11 stays open because the artifact-supplier cannot close it — what is withheld is the tally, not the work (consolidated)

**By:** Mouse (`mouse-proof-ledger`, `mouse-ledger-provenance-and-the-bound`), Morpheus (`morpheus-census-is-not-a-criterion` items 1–2, `morpheus-withheld-is-the-tally-not-the-work` items 1–2)

**The ledger:** `OpStatus::Live` is retired; the registry declares only `Staged(why)`/`Ready`, and claimability is derived per form from a harness-generated proof ledger (`evidence/proof_ledger.jsonl`, 9 entries, `include_str!`-baked so a build cannot claim a form whose proof is absent from the binary claiming it). Key format is normative (one `::`, five `/`, no empty component) so an expression difference and a path difference are mechanically distinguishable (§8.7). The escape hatch (`CLAIM_UNPROVEN`) accepts only a list of proof keys — no `1`/`true`/`*` — because a hatch that opens with one token gets opened once and never closed; using it costs a WARN, a counter, and a non-zero `epctl --check-counters` exit; `--allow-unproven` downgrades, never erases, the WARN. **Phi-3.5's claimed count fell 355 → 0** on the ledger's arrival — accepted explicitly by Morpheus, not softened, predicted in writing beforehand and confirmed exactly; the fall is bounded to 8 distinct proof obligations, mechanically discoverable because every claim-log audit line now carries `proof_key`.

Absent is treated exactly like zero (a parser accepting an absent field lets the claim table write the ledger by omission); a quoted count is not a count; the check is enforced identically on the generator (raises) and the reader (`--check` fails, `parse_ledger` faults) so it cannot be walked around by using the other tool. A baked-vs-disk digest disagreement **refuses**, never warns — `Ledger::faults` non-empty makes every lookup `Faulted`, because a WARN would leave a run claiming from evidence nobody can read. A miss is three findings, never one bool: `LEDGER-FAULTED` outranks `KEY-ABSENT` (a faulted run has no reading about any form); `NEVER-ATTEMPTED` is derived from `proven_key_lookups == 0` and never counted (recording it would itself be the lookup it asserts did not happen).

**Three of Mouse's constructions are named in criterion 11's row as meeting the standard: (a) provenance an enumeration cannot forge; (b)(iii) the identical-file/two-armed control that makes the other arms detections rather than always-red checks; (d) `NeverAttempted` derived and never counted.** Row 11 closes on **(c)** — Trinity's, `ledger_hits` shown to move with its input — and on nothing else. **Morpheus's restoration:** the sentence *"what is withheld is the tally, not the work"* was lost in a merge where neither side was a superset; he asked to have it re-added rather than have the coordinator splice prose, and restored it verbatim — *"a lead who can only ever withhold is running a different instrument from the one he thinks he is."* Mouse's evidence (the ledger, the two-armed control, the `MatMulNBits`±`zero_points` pair, `355→0`) is not rejected, not doubted, not diluted by staying uncounted.

**The general form, written into row 12 as well:** *the census answers whether a mechanism ran; a criterion answers whether a claim is falsifiable. A census line can never discharge a criterion, and a criterion's failure is never evidence that a mechanism is unwired.* A wired mechanism beside an undischarged criterion is the normal state of a row being taken seriously.

### 2026-08-02T02:03:46-07:00: R9's third generalisation — a criterion is discharged only by an observable that changes when the claim is false; and R13's dangling-reference class widens to phantom keys and decayed line numbers (consolidated)

**By:** Morpheus (`morpheus-phantom-key-is-r13`, `morpheus-census-is-not-a-criterion` items 3–4)
**Why consolidated:** two rulings on the same day, both explicit refusals to mint a new rule number, both extending an existing rule's *scope* rather than its remedy — R9 to criteria, R13 to references generally.

**R9's third generalisation:** *a criterion is discharged by an observable that changes when the claim is false, never by one that is true whatever happens.* Three specimens in one day: RAI-011's "always evaluated, no branch in front of it" satisfied by an unconditional early return **inside** the gate (`bypasses` stays 0 forever, every word of the criterion true); Link's screen reading `ONNXRUNTIME_EP_VULKAN_TRACE_FILE`, a variable nothing defines, reporting the same value on every run it ever made and would have done so had the tracer been deleted; Switch's assertion comparing two values both exactly `0.0`. The class is indifferent to polarity — an always-false screen and an always-true screen are equally blind. Operational form: *before recording a criterion met, name the run that would have failed it, and say whether that run is reachable; if not reachable, the criterion is unfalsifiable and the tally should say so rather than say MET.*

**The dangling reference (R13 amendment 1) generalises beyond the defaulting lookup:** `alloc_device_spans` had no emitter anywhere in the repository — the probe (`probe_sec65.py:89`) requested it via `data.get(k, '<absent>')`, so it printed `'<absent>'` on every run since it was written, raising nothing. **A defaulting read converts a reader-side failure into a subject-side value, silently** — admissible only where absence is a genuine finding about the subject and named as such. This is R13's costume on R10's face: `'<absent>'` reads as "the counter reported nothing" when the fact is "there is no such counter" — opposite diagnoses, opposite fixes, rendered indistinguishable by one token doing the work of two. **The class widens to any reference that resolves to nothing and reports that as a value** — a key with no emitter, an env var nothing defines, and **a line number** (`partition.rs:475`, which silently became a different statement once the file moved) — the worst of the three, because there is no lookup to fail; the reader performs it by hand and receives confident nonsense. Remedy: cite the symbol, not the line; a symbol that stops existing produces a reader-visible `ERROR(instrument)` (failed search), a line number that stops being right produces none.

**Standing obligation adopted: the key census.** Every key a probe or report requests must resolve, by exact string match, to a literal emitter in the source producing that artifact; an unresolvable key is `ERROR(instrument)`, never a value. Two tiers required: runtime (the shared read helper refuses at the point of request) and static (a census over every probe, seeing keys on unexercised paths) — owner Tank, with Niobe, importing `audit_instruments.py`'s existing five-state vocabulary; a planted-phantom positive control is required or the check has unknown polarity. §6.5.3 discharged (Niobe restored the three dropped companion keys to `probe_indexspace.py`'s extract). `span_accounting()`'s own defect (`NOT_A_NUMBER` fires on a phantom key exactly as it would on a genuine non-numeric reading, describing it as "the type is the answer" — false and reassuring) must split pending the census landing, so a phantom key reports `ERROR(instrument)` rather than `NOT_A_NUMBER`.

**Why consolidated:** both are instances of *the checker (or the process) mis-attributing a result*, one about a classification, one about a build artifact — Morpheus rules on both in the same record, both caught by Mouse himself.

**R12's fourth generalisation: for a test result, the frame is the binary that ran it.** Two specimens, both Mouse's, both self-caught: a build in the shared worktree `C:\Users\justinchu\dev\ep-vulkan-mouse` linked a sibling agent's in-flight `registry.rs`, producing a false `ledger_gate: ALL-DECLINED` he nearly wrote up as a finding; and **`Copy-Item` preserves the source file's `LastWriteTime`**, so cargo's mtime-based fingerprint does not notice a restore-from-backup and silently re-runs the previously-compiled **mutated** binary — a persistent false failure Mouse came close to "fixing" by weakening a correct assertion, the most expensive outcome available. Not Windows-specific — the trap exists wherever a build system fingerprints on mtime alone, and a false red "fixed" by softening the assertion it fired on converts a working control into a decoration in one commit.

### 2026-08-02T02:03:46-07:00: No dispersion statistic can certify a benchmark against a uniform bias — the load guard is not independent of whole-series RSD, `MARGINAL_TAIL` must never publish its withheld median, and the "empty gap" closed (consolidated)

**By:** Niobe (`niobe-marginal-tail-must-not-publish`, `niobe-tail-boundary-cross-check`), Switch (`switch-dispersion-cannot-certify`, `switch-load-guard-same-ordinal-rsd`)
**Why consolidated:** Switch built the same-ordinal-RSD load guard and initially sold it as independent corroboration of the tail test; Niobe, independently, computed the same correlation and reached the same conclusion; Switch then recomputed it himself rather than quote her, withdrew his own claim, and both converge on one structural result plus one shared worked example (`baseline_certified`).

**The structural result:** *no statistic computed from inside a series can detect a bias that scales the whole series* — dispersion is invariant under multiplying every sample by a constant, so a uniformly-wrong run is indistinguishable from a uniformly-right one to any measure of spread, existing or future. Same-ordinal RSD and whole-series per-inference RSD are **not two independent checks** — Niobe measured Spearman ρ=0.903/Pearson r=0.964 over 28 traces; Switch, recomputing independently rather than quoting her, got ρ=0.919/r=0.970 over 29 — because a disturbance that scales a whole submission moves every dispatch inside it together, so same-ordinal RSD is approximately a re-selection of the same quantity, not a second opinion. Switch's own earlier record had sold the agreement as independence and is withdrawn: *"Agreement between two statistics is evidence for redundancy... the third time this project has been bitten by a confirming result receiving less scrutiny than a contradicting one."* Measured value-add of the guard: **0 new refusals over 29 traces** (9 flagged, all 9 already refused by the tail's own floors) — its real value is localisation (per-dispatch, not per-sum) and that it still holds if a `MARGINAL_TAIL`'s withheld median is ever published.

**The worked example, found independently by both and by every dispersion measure this project owns:** `trace_gemv_baseline_certified_dev0.json` is the **cleanest trace in the census on whole-series RSD (0.12%), tail RSD (0.1163%, 4th tightest) and same-ordinal RSD (0.36%, cleanest)** — publishing `STEADY` at n=46/100% coverage/zero discarded — and it is **21.4× wrong**. Only `bench/device_state.py` (peak SM 210 MHz against a 3105 MHz board maximum) refuses it, because its evidence comes from outside the series. This is the third appearance of one pattern this project has now named explicitly: *precision is not merely uninformative about accuracy on this instrument, it is anti-correlated with it* — a board stuck at idle clock, a foreign tenant, or a short selected window each **reduces** dispersion. **Consequence adopted:** `MARGINAL_TAIL` withholds its median under a distinct key (`withheld_median_ms`) that no consumer treats as a median — proposed as DESIGN.md clause 8c: *a verdict that refuses to publish must not expose the value it refused... a withheld figure is not a figure held to a higher standard; it is one whose apparent precision is an artifact of the selection that produced it.* Obligation 8 (device-state, out-of-band) is ruled not replaceable by any in-band statistic, on this ground alone. Switch's own "empty gap" headline (10.507%–35.313%, no trace in it) did not survive a 29th trace (`switch_resid`, 20.787%, margin collapsed 1.77×→1.04×) — not re-fitted to restore the old band; published as a recomputable sensitivity table instead, with the general lesson that *an "empty gap" is a statement about the traces you happen to have and decays as you collect more.*

**Localisation, kept:** `ab_p1_long` (35.31%→3.90% normalised, 88.9% explained) is `SUBMISSION_LEVEL`; `contended3` (41.11%→50.43%, −22.7%) is `PER_DISPATCH`, the signature foreign-GPU-work ought to produce — flagged to Niobe as a partial answer to whether foreign GPU work moves `gpu_steady_tail()`. Three instruments, three failure modes, none collapsing into another: device state (wrong level), the load guard (non-stationary run), the coverage floor (unrepresentative selection). **No figure needed retracting**: the coordinator's 12.1847 ms/inference NVIDIA figure is from a different artifact (`phi35-certified-dev0.json`, `SOLE_TENANT`, `QUOTABLE`) than `baseline_certified` (a gemv microbenchmark, `WITHHELD`) — conflated in a passing remark, corrected without needing a retraction.

### 2026-08-02T02:03:46-07:00: A cross-file test failure was a module *name* collision, not a `sys.path` leak — the prescribed fix would have left the bug live

**By:** Niobe (`niobe-module-name-collision-not-syspath`)

The failure text, read rather than accepted (R13), was `AttributeError`, not `ImportError` — the module was found, it was the wrong module. **`import` consults `sys.modules` before `sys.path`**: two files were both named `device_state.py` (`bench/device_state.py`, her tenancy/SM-clock companion; `ci/device_state.py`, Link's lane-level obligation-8 registry), and whichever imported first bound the global name for the rest of the process. `sys.path` ordering decides which file wins the race; it does not decide that there is a race — the race exists because two files share a base name. Verified as one invocation: `pytest bench/ ci/ tests/ops/` → 402 passed, 321 skipped, 0 failed. **The general shape matches Tank's same-session finding in Rust — "wiring an instrument changed which tests share state."** Nothing was locally wrong in either file; the failure exists only in the union, and the prescribed remedy for the union would have addressed the ordering of the race rather than its existence.
